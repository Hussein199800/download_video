# سَيْل 1.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Full download manager (sizes, pause/resume, reorder, batch, notification actions, auto-retry, network resume), scheduling, WhatsApp statuses, automatic Server 2 (NewPipe) fallback and a Components page — on Android 8+.

**Architecture:** Kotlin stays the source of truth: `JobStore` gains manager fields; pure Kotlin objects (`Failure`, `Retry`, `Schedule`, `ServerPolicy`, `StreamPicker`, `StatusPaths`) hold every decision and are JVM-tested; `DownloadWorker` orchestrates; `Server2` wraps NewPipe + HTTP + FFmpeg. JS keeps argv building and presentation.

**Tech Stack:** as 1.0 + `com.github.TeamNewPipe:NewPipeExtractor:v0.26.5` (JitPack), `com.android.tools:desugar_jdk_libs_nio:2.1.5`, `androidx.documentfile:documentfile:1.1.0`.

**Spec:** `docs/superpowers/specs/2026-10-30-sayl-1.1-manager-design.md`

## Global Constraints
- minSdk 26, compile/target 36, coreLibraryDesugaring nio. Version `1.1.0` / code `2` in the three version files.
- No speed limit option anywhere (owner's request).
- Arabic UI, colour per kind; new class `c-wa` (WhatsApp green `#25d366 → #128c7e`). All questions/labels Arabic (CLAUDE.md).
- Job states: `queued | running | paused | waiting_network | retrying | done | failed | canceled`. "Active" = queued, running, waiting_network, retrying.
- Retry delays: 30 s, 120 s, 600 s, then 600 s; default max attempts 5 (setting 0/3/5/10).
- Connections setting 2/4/8, default 4; aria2 default **off**.
- Server 2 services: YouTube, SoundCloud, PeerTube, Bandcamp, media.ccc. Auto yt-dlp update before switching only if last update > 6 h ago.
- Statuses saved to `Download/سيل/حالات واتساب/`.

## Review Focus
1. Pause during the merge (FFmpeg) step → resume restarts the merge; no corrupted file in Download. Test: Task 2 JobStore pause keeps `work/<id>`; worker only publishes after a successful exit.
2. Quiet window crossing midnight (23:00→06:00) at 05:59 and 06:01 → due / not due. Test: Task 4 ScheduleTest.
3. Batch paste with blank lines, duplicates, text around links → only unique URLs, order kept. Test: Task 5 links test.
4. Server 2 when no stream ≤ requested height exists → pick the lowest available rather than failing. Test: Task 6 StreamPickerTest.
5. Status folder missing (WhatsApp not installed) → friendly empty state, no crash. Test: Task 7 e2e mock + StatusPathsTest.
